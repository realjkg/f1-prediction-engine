# Release 1.0: age 8+, privacy, and supply chain

## Product scope for 1.0

The F1 Pit Wall app is an informational racing-analysis and non-monetary
prediction game intended for ages **8 and up**. Users may make picks for
fictional points and view explanations, race history, and historical or
clearly identified experimental simulation artifacts.

For the 8+ experience: **no wagering or betting**, gambling links, real
money, deposits, withdrawals, paid picks, prizes of cash value, or gambling
promotions. There is no real-money currency conversion. No public player
profiles, direct messaging, advertising, location targeting or behavioral
tracking should be introduced into this product without a separate
privacy and safety review.

There are no nicknames, profiles or accounts. Game choices and preferences
live only in the page's memory and reset on reload (see
[PRIVACY.md](PRIVACY.md)). Do not ask a child for a birthdate, government ID,
address, precise location or payment information to unlock this free game.
An accessible reset action clears this visit's choices. All content and
language should remain suitable for school-age users.

This statement is a product requirement, **not a certification** of COPPA,
children's privacy law compliance, app-store age classification, or privacy
approval. Before public distribution, conduct a privacy review including
SDK and browser analytics, network traffic, logs, app-store disclosures,
third-party processors, accessibility, customer support, and parental
rights where relevant.

## Separate adult-only future product

Any future adult-restricted application requires an independently reviewed
product boundary, legal/territorial assessment, credential handling, age
and identity assurance where lawful, separate accounts and data stores,
controls preventing minor exposure, security validation, and an explicit
release decision. No adult-only capability is part of this release.
The 8+ app must never display or provide access to wagering features.

## Supply-chain inventory and release evidence

The CycloneDX 1.6 inventory generated by
`scripts/generate-sbom.py` includes the exact pinned Python runtime and
development lockfiles plus npm lockfile packages. A SHA-256 manifest names
all input locks; an identical output is regenerated in CI and uploaded as
the `f1-cyclonedx-lockfile-inventory` artifact. The engine image creates a
matching partial SBOM under `/app/data/sbom/`, and GET `/api/supply-chain`
verifies the manifest and source locks before returning inventory to the
read-only UI. If absent, stale, or modified, it responds with a typed 503.

**Release 1.0 still requires a broader attested SBOM**, including base
images/OS packages and both native mobile dependency graphs. The container
image digest, installed package inventory, build provenance, code commit,
test suite results, and signatures should all link to the same release
commit. This initial SBOM reports `releaseReady: false`; a green inventory
test must not be confused with full supply-chain attestation.

safety downgrades.
