# Language and editorial conventions

Write all original repository prose, UI copy, comments, documentation, examples, and new tests in **U.S. English (en-US)**. Use American spelling and vocabulary consistently: **color, behavior, optimize, analyze, organization, authorization, license, center, tire, gray, canceled, and modeled**. Refer to the sport as Formula 1 or F1; do not copy regional spellings into our own race analysis.

Apply this to generated text, issue and pull request descriptions, model cards, dashboards, release notes, and user-facing API messages. Review text that AI assistants produce before committing it. Keep wording concise, natural, and specific.

**Compatibility exceptions:** Never blindly rename published API routes, database fields, serialized JSON keys, source identifiers, dependencies, exact commands, filenames, legal notices, trademarks, official names, source quotations, or third-party license text just to adjust spelling. Preserve these where changing them would alter meaning, attribution, or software behavior. If a migration is genuinely needed, implement a separately reviewed compatibility change with tests.

For writing changes, check the current text for regional spellings before marking the task complete. Preserve historical evidence and do not rewrite data provenance.
